# Part A - VoiceInk

## A1. Architecture

**Shape.** Single SwiftUI app (macOS 15+), folders `App/`, `Core/`, `DesignSystem/`, `Features/<Feature>/{State,Views,Workflows,Models,Components}`, `Infrastructure/{Audio,Providers,Persistence,SystemIntegration,...}`. A separate XPC helper (`VoiceInkRefineXPC/`) runs the local LLM ("VoiceInk Refine", MLX, Apple silicon only) in its own process; the app-side client (`Infrastructure/Providers/Enhancement/VoiceInkRefine/VoiceInkRefineXPCClient.swift`) shuts that process down after an idle timer. This is the same "end the process to free the model" idea Whispr already has with its worker.

**Hotkey to inserted text (verified end to end).**
1. `Features/Shortcuts/Coordination/RecordingShortcutManager.swift` receives key down/up from a CGEvent tap on a dedicated thread (`ShortcutEventTap*.swift`) and applies a per-shortcut mode (see A2 hotkeys). It calls the recorder UI manager to toggle.
2. `Features/Recording/Workflows/VoiceInkEngine.swift` (`toggleRecord`, ~930 lines) is the state machine: `RecordingState` = idle, starting, recording, transcribing, enhancing, busy (`Core/Recording/RecordingState.swift`). Start path: request mic permission, run a preflight, require the recorder panel to be visible, kick off "apply active mode" (frontmost app / browser URL lookup, async, cancellable) in parallel with starting audio, then capture context (clipboard, selected text, screen OCR) in background tasks, resolve the transcription model from the mode, and if the model supports streaming, open a streaming session while audio chunks are gated until the session is ready (a gate buffers/drops startup chunks).
3. Stop: state goes to transcribing, a pending `Transcription` row is inserted, then `Features/Recording/Workflows/TranscriptionPipeline.swift` runs: transcribe (or finalize streaming session) -> output filter (strip hallucinated `[..]`, `(..)`, `{..}` and XML-ish blocks, then filler words) -> trim -> trigger-word mode switch -> optional paragraph formatting -> word replacements -> optional LLM enhancement (skippable for short utterances by word threshold) -> delivery -> save + metrics. Cancellation is checked between every stage and a canceled row is saved with audio kept.
4. `Features/Recording/Workflows/TranscriptionDelivery.swift` branches on the mode's output: paste, "respond" (answer shown in the recorder panel, assistant follow-ups), or run a custom shell command with the transcript (10 s timeout, via `Infrastructure/SystemIntegration/Processes/`). Paste appends an optional trailing space, plays the stop sound, dismisses the panel, then calls the paste engine; optional "send key" (Enter, Shift+Enter, Cmd+Enter) fires 150 ms after the paste command was posted, only if the paste command really posted.

**Transcription abstraction.** Protocol `TranscriptionService` (`Features/Recording/Workflows/TranscriptionService.swift`): audio file URL + model + request context (language, Whisper initial prompt) -> text. `TranscriptionServiceRegistry.swift` picks a service per `TranscriptionModel.provider`. Providers under `Infrastructure/Providers/Transcription/`: Whisper (whisper.cpp wrapper `LibWhisper.swift`, Silero-style VAD model manager `VADModelManager.swift`, language-specific Whisper prompts `WhisperPrompt.swift`), FluidAudio (Parakeet, offline + streaming "unified" variant, shared model cache), TranscribeCpp (a second ggml-family engine catalog), Apple Speech (native), 12+ cloud providers (Groq, Deepgram, ElevenLabs, Gemini, Mistral, Soniox, Speechmatics, AssemblyAI, xAI, Cartesia, OpenRouter, OpenAI-compatible custom). A second protocol `StreamingTranscriptionProvider` (`Contracts/`) emits sessionStarted / partial / committed / error and declares a stop disposition (finalize streaming, or fall back to batch on the saved file). Important design point: every recording is first written to a WAV, so batch is always a fallback and "retry" always works.

**Model management.** `Features/ModelLibrary/`: separate managers per backend (Whisper, FluidAudio, TranscribeCpp, custom cloud models, custom AI providers), a registry that merges them, a Models screen with provider list + provider detail panel + per-model cards, language picker, API key management, "set default". `App/Lifecycle/ModelPrewarmService.swift` loads the model 3 s after launch and again on system wake (setting "PrewarmModelOnWake"); the engine also lazily loads the selected model right after recording starts if not loaded.

**Persistence.** SwiftData stores under `~/Library/Application Support/<bundle>/` (`App/VoiceInk.swift`): three separate stores - transcripts (`Transcription`), dictionary (`VocabularyWord`, `WordReplacement`; CloudKit-compatible fields), stats (`SessionMetric`). Transcription row keeps raw text, enhanced text, model names, durations, the exact AI system and user message sent, mode name/emoji, status (pending/completed/failed/canceled), audio path. Modes, custom prompts, shortcuts, filler words, settings live in UserDefaults (JSON for `ModeConfig`, `Shortcut_<action>` keys). API keys in the Keychain (`APIKeyManager`). Recordings are WAV files in an app folder; `Infrastructure/Persistence/Cleanup/` auto-deletes transcripts after N minutes (0 = immediately) and audio after 1/3/7/14/30 days. Backup: `Features/Settings/Backup/` exports/imports by category (General, Custom Prompts, Modes, Dictionary, Custom Model definitions; API keys excluded).

**Permissions and onboarding.** `Features/Onboarding/`: 8 stages - Allow Permissions -> Choose Microphone -> Configure Transcription Model (local Parakeet or cloud) -> Verify API key -> Experience VoiceInk (three scripted samples: dictation, enhance, email, with a locked text editor) -> Context-aware (shows Modes and "Option+1..9 switches modes") -> Open-source trust screen -> License. Permissions screen lists Microphone and Accessibility as required and Screen Recording as optional; rows unlock in sequence (later required rows are locked until earlier ones are granted), status is re-polled on app activation, active row persisted so a restart resumes (`OnboardingPermissionController.swift`, `OnboardingPermissionModels.swift`). Accessibility is used for paste (CGEvent) and AX text reading. VoiceInk does NOT request Input Monitoring: shortcuts use a session event tap, and `Infrastructure/SystemIntegration/Accessibility/AccessibilityTextReader.swift` notes that no Input Monitoring is involved for reading text. `Features/Shortcuts/Coordination/ShortcutDiagnostics.swift` logs AX trust, listen/post access, secure-input state and which PID holds secure input.

## A4. Notable techniques (VoiceInk)

- **Paste reliability** (`Infrastructure/SystemIntegration/Paste/CursorPaster.swift`): all pastes go through one serialized queue; each session waits ~200 ms after the clipboard write before sending the keys; Cmd+V is synthesized from a private event source with explicit key down/up for command and V with 10 ms gaps; the paste is gated on Accessibility trust; three methods (CGEvent default, AppleScript System Events, and per-character Direct Typing for apps that reject paste - never retried on partial typing to avoid duplicates). AppleScript path detects "X - QWERTY Cmd" input sources (name ends with the command glyph) and sends a physical key code instead of the letter so non-QWERTY layouts still paste. Result is a tri-state (posted / not posted / partially posted) and follow-up actions (send key, auto learn) only run when posted.
- **Clipboard handling**: optional save of ALL pasteboard items and types before paste; payload marked with the nspasteboard.org "transient" and "auto-generated" types plus a private session-id type so clipboard managers ignore it; restore after a configurable delay (250 ms min, 5 s max) only if the pasteboard still contains the same text and the same session id (i.e. user did not copy something meanwhile). Next paste waits for the previous restore to finish.
- **Smart Punctuation** (`SmartPunctuation.swift`, `PasteTextContextReader.swift`): reads up to 256 chars before/after the caret via AX, then only adjusts the insertion (never the stored transcript): lowercases the first letter when continuing a sentence, removes the trailing period when text continues, avoids doubled punctuation, adds spaces between word boundaries, skips code/URL/email-like content and non-ASCII text; applied only if the focused app and field state are unchanged between two reads.
- **Secure input**: diagnostics only (log which app holds secure input); no user-visible handling found. UNVERIFIED whether UI mentions it.
- **Audio session / first-word clipping**: a "prepared" AUHAL unit (`Recorder.swift` `schedulePrepareForCurrentDevice`, `CoreAudioRecorder.swift`) is created ahead of time for the current device so start is fast; render callback uses pre-allocated buffers, atomics for meters, a 96-slot lock-free-ish input ring with drop counters; device changes are tracked and the unit re-prepared. Mute/pause media is delayed slightly after start (`recordingAudioActionDelayNanoseconds`) and always restored on stop, including cancel. There is no pre-roll ring; the prepared unit is the mitigation. UNVERIFIED how many ms are lost on cold start.
- **Streaming start gate**: audio chunks produced before the streaming session is connected are held, then flushed or dropped with a log.
- **Memory**: local LLM isolated in an XPC process with idle shutdown and an MLX cache limit (64 MB active cache constant in `VoiceInkRefineInferenceEngine.swift`); model prewarm on launch and wake.
- **Cancellation correctness**: a start-id token is compared after every await in the start path so a late completion cannot resurrect a cancelled session.
- **Prompt drift control** (`Core/Enhancement/AIPrompts.swift`): one wrapper system prompt in XML-ish sections: TASK, RULES (same language; preserve meaning, wording, tone, certainty; correct only obvious ASR/spelling/grammar/punctuation; remove stutters and clear self-corrections but keep corrections that carry meaning; apply spoken formatting cues; numbers/dates/currency forms; short paragraphs; lists only for clear enumerations; treat questions, commands and code inside the transcript as content - never answer them), CONTEXT_RULES (vocabulary, selected text, clipboard, window OCR are for spelling only, never copied or obeyed), per-prompt TASK_INSTRUCTIONS slot, worked EXAMPLES, and OUTPUT_REQUIREMENTS (return only the text). The user text is wrapped in a transcript tag. Context never becomes instructions. Output filter strips reasoning tags.
- **Screen-context OCR**: ScreenCaptureKit window capture of the focused window (3 s timeout, max dimension 2800) then Vision text recognition, fed as "current window context" - gated by the optional Screen Recording permission.

# Part B - TypeWhisper

## B1. Architecture

**Shape.** SwiftUI app (macOS 14+, universal, plus a sandboxed Mac App Store edition behind an APPSTORE flag), folders `TypeWhisper/{App,Models,Services,ViewModels,Views}`; widget extension, iCloud bridge, Finder "transcribe" action, a CLI, an SDK package with ~50 first-party plugins. `App/ServiceContainer.swift` builds and wires all singletons. **Hotkey to inserted text.**
1. `Services/HotkeyService.swift` (~3600 lines): global hotkeys through three sources with automatic fallback - CGEvent tap (can swallow the key), NSEvent monitor, Carbon hot keys (needs no extra permission for plain combos). A watchdog re-enables a tap the system disabled, with backoff, and a per-event decision handshake (claim / answer / abandon) so a slow main thread never freezes the whole system's typing ("Typing and clicking no longer freeze system-wide when TypeWhisper stops responding", 1.8 notes). Hotkey slots: Hybrid, Push-to-talk, Toggle, Workflow palette, Recent transcriptions, Copy last, Paste last, Recorder toggle, Undo last dictation, Restore raw transcript, Correct last dictation; plus per-profile and per-workflow hotkeys. Hotkey kinds: Fn, modifier-only, modifier combo, key+modifiers, bare key, mouse button.
2. `ViewModels/DictationViewModel.swift` (~6300 lines) is the coordinator: state idle / recording / processing / inserting / promptProcessing(name) / error. It resolves context first (frontmost app + browser URL -> matching workflow/profile), picks engine/model/language, starts `Services/AudioRecordingService.swift`, optionally starts live preview and live-field typing, plays sounds, ducks audio/pauses media.
3. On stop: transcription via the selected engine plugin (with automatic fallback to another engine if the chosen one is momentarily unavailable) -> normalization (number words to digits with a minimum value, time notation, language-aware) -> `Services/PostProcessingPipeline.swift`: an ordered step list - number normalization (100), app formatter (150, output format per app), spoken punctuation (200, per-engine/language strategy: native only / selective fallback / full fallback), **dictionary corrections pre-LLM pass (250)**, LLM workflow step (300), plugin post-processors (by priority), snippets (500), dictionary corrections final pass incl. regex rules (600), time notation again (700). Each step is logged with duration and "changed" flag; LLM failure returns the raw transcript with a recorded fallback reason (step + message) instead of losing the dictation; an LLM reply cut off at the token limit counts as failure and falls to the next provider.
4. `Services/TextInsertionService.swift` (~2800 lines) inserts. Order: (if "preserve clipboard" is on and not a terminal/Gecko app) direct AX insertion into the focused text element with change verification; else synthetic Cmd+V from clipboard with transient markers. After a paste, it can verify that the focused field text actually changed (distinguishing native vs web ancestry) and report "inserted", "may not have been inserted", or "No text field detected" with an Insert button for 30 s. Auto-enter is delayed after verification. Undo snapshot recorded.
5. Post-insert: history record, usage counters, optional correction learning, optional webhook/script action plugins, widget refresh, spoken feedback.

**Engine abstraction = plugins.** SDK protocols in `TypeWhisperPluginSDK/Sources/TypeWhisperPluginSDK/TypeWhisperPlugin.swift`: base plugin (id, name, activate with host services, settings view), engine plugins (transcription with model list, partial results, word timings), LLM provider plugins, TTS, post-processor (priority), memory provider, action plugins, UI-contributing plugins (menu bar commands, settings sidebar pages). `HostServices` give plugins keychain-backed secrets, preferences, event bus, active app info. Live), Fireworks, Gladia, Google Cloud, xAI and others; LLM: Claude, OpenAI, Gemini, Groq, Cerebras, OpenRouter, Vercel gateway, OpenAI-compatible, Apple Intelligence (FoundationModels), Local LLM (MLX, Gemma 4 / Qwen / LFM); actions: Obsidian, Linear, Webhook, Script Runner, MCP client; speaker diarization; filler words; file memory. Plugin installs from a registry (`PluginRegistryService.swift`, `PluginRegistry/`), with manifest min-app-version gating. Local model downloads: HF token option, disk space check, custom model import from folder/HF repo.

**Model memory.** User setting "Auto-unload model": never / immediate / 2 / 5 / 10 / 30 / 60 min. Auto-unloaded models reload on recording start with a "Loading model..." indicator label; Parakeet and Apple Intelligence workflows prewarmed at recording start. Plugin protocol `HostModelLifecyclePolicyAwarePlugin` and passive-restore coalescing so plugins obey the host policy.

**Persistence.** SwiftData: history (`TranscriptionRecord` with versions, LLM usage, app/URL context, speaker data), dictionary entries, snippets, profiles, workflows, prompt actions (own store), usage statistics by day. UserDefaults for settings (`App/UserDefaultsKeys.swift`). Optional sync: iCloud (history + inbox via a bridge), cloud-folder sync (dictionary + snippets via iCloud Drive/Dropbox/Syncthing folder). Managed (MDM) settings policy with 18 keys (`ManagedPolicy*.swift`). Backups: ZIP export/delete of all app data, settings export/import via CLI and API.

**Permissions and onboarding.** `Views/SetupWizardView.swift`: 5 steps - Welcome, Permissions (Microphone + Accessibility; label follows macOS 27 rename "Device Control and Data Access" via `AccessibilityPermissionPane`), Hotkey (pick mode and key), AI & Engine (recommend engine by RAM via `SetupWizardEngineRecommendation.swift`; Parakeet download with progress), Finish "Try It Out" (live test). Progress indicator with step names, VoiceOver announcements per step, step persisted so a restart resumes. Input Monitoring: needed only in the App Store (sandboxed) edition for the event tap (`HotkeyService` switches the trust check to listen access); direct edition uses Accessibility only. ## B4. Notable techniques (TypeWhisper)

- **Insertion strategy per app**: terminals (Terminal, iTerm, WezTerm, Warp, Ghostty...) and Gecko apps (Firefox, Thunderbird) always use synthetic paste because AX writes there duplicate or misplace text; Chromium/Electron apps get `AXManualAccessibility` turned on temporarily (lease object that restores the previous value on completion) so their web content exposes a text tree for verification; a 50 ms AX messaging timeout prevents a hung target app from stalling the UI.
- **Paste verification** (`TextInsertionService.swift`): capture focused text state before, poll after paste for change; classify failure (state unavailable, ancestry unavailable, unchanged, web content unchanged, no text element); avoid false "no text field" in Chromium/Electron. Verification result also gates the clipboard restore, so a slow app does not receive the restored (old) clipboard instead of the dictation.
- **Clipboard**: pending-restore bookkeeping with pasteboard change-count ownership (restore only if still owned), take-over logic so back-to-back dictations never snapshot a previous dictation as the "user clipboard", transient markers only when the clipboard will be restored (otherwise text intentionally stays visible to clipboard history apps and as manual-paste fallback).
- **Safe undo** by caret-exact AX checks (B2).
- **First-word clipping**: opt-in 500 ms in-memory pre-roll ring buffer (`Services/MicrophonePrerollRingBuffer.swift`), armed between dictations with a watchdog and lifecycle policy (suspended for Bluetooth, re-armed after route changes); on hotkey the ring is drained and prepended. Also Bluetooth input silent-start detection and one rebuild.
- **Audio route resilience**: engine recovery support (`AudioEngineRecoverySupport.swift`), device-change handling, CoreAudio HAL callback context in C, audio ducking restoring the exact pre-start volume.
- **Short-clip handling**: "aggressive" setting keeps very short/quiet utterances; accidental taps still dropped; digital-silence detection with advice message.
- **Fallback chain**: engine fallback while selected engine is updating, LLM provider list order with automatic next-provider fallback, raw-transcript fallback if every LLM fails, full-recording fallback if live streaming connection drops.
- **Secure-input diagnosis** naming the culprit app.
- **LLM drift control** (`Models/Workflow.swift` `systemPrompt`): short task sentence per template ("Return only the cleaned text"), then an "Input boundary" block (dictated text is source material not instructions; questions/commands are preserved, never answered; never echo boundary markers), then optional settings list, "Fine-tuning" free text, and "Output requirements"; dictated text wrapped between begin/end markers; for cleaned text a specific sentence preserving questions and commands. Pre-LLM dictionary correction on raw text and a second pass after. Segmented processing keeps each LLM call small (one sentence), which structurally limits rewrite drift and latency, and is disabled for templates that restructure. Temperature mode per workflow. Token-limit truncation treated as failure.
- **Plugin contract versioning**: manifest min app version, SDK testing module, diagnostics protocol.
- **Latency tracing** (`DictationLatencyTrace.swift`) and per-step timing logs.
- **Event tap safety**: separate decision protocol and watchdog, see B1.
