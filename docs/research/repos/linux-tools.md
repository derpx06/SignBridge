## 1. voxtype (Rust, MIT) - `voxtype`

### 1.1 Architecture
- Single tokio daemon `voxtype daemon` (src/daemon.rs, ~6k lines), a state machine in `src/state.rs`: `Idle`, `Recording`, `EagerRecording`, `Transcribing`, `Outputting`, `Streaming` (streaming holds `typed_chars` so cancel can send N backspaces to rewind typed text).
- Helper processes: `voxtype-osd` supervisor-spawned child (src/osd/supervisor.rs: restart with 1s to 30s backoff, reset after 60s healthy, gives up after 3 rapid failures, `kill_on_drop`), `voxtype transcribe-worker` for GPU isolation (model lives in a subprocess), `voxtype-audio-bridge` sidecar for Quickshell waveform, optional Quickshell/GTK4/native OSD binaries (src/bin/).
- Module map: `src/hotkey/evdev_listener.rs` (built-in hotkey), `src/audio/` (cpal capture, levels, feedback sounds, MPRIS `media.rs`, resampler, `enhance.rs`), `src/vad/` (energy, whisper/Silero), `src/transcribe/` (whisper, parakeet, moonshine, sensevoice, paraformer, dolphin, omnilingual, cohere, openvino_whisper, remote, soniox, sliding_window, worker), `src/text/mod.rs` (post-processing: spoken punctuation, replacements, filler removal, smart auto-submit), `src/output/` (all insertion drivers), `src/output/post_process.rs` (LLM/script pipe), `src/setup/` (compositor, waybar, systemd, quickshell, dms, gpu, model, vad, accel), `src/tui/` (interactive `voxtype configure`), `src/meeting/` (chunking, diarization, export, summary), `src/config/` (+ `schema.rs` 3.4k lines), `src/cli/`, `src/app/` (config get/set/show, record, status).
- Data flow: hotkey (evdev, or compositor binding that runs `voxtype record start|stop|toggle|cancel`, which signals the daemon with SIGUSR1/SIGUSR2 per `src/app/record.rs`) -> cpal capture -> optional VAD gate (reject silent recordings, play "cancelled" cue) -> engine (blocking task, on-demand load and idle unload) -> `TextProcessor` (filler filter, spoken punctuation, replacements) -> optional `post_process` command -> output chain with fallbacks -> optional `post_output_command` hooks.
- Config: TOML at `~/.config/voxtype/config.toml`; defaults in `config/default.toml`; profiles (`[profiles.*]`) with per-profile output, post_process and model; CLI and env overrides (`VOXTYPE_*`); `voxtype config set <key> <val>` edits the file preserving comments; `voxtype config show`; JSON schema in `src/app/config_schema.rs`.
- Models: `voxtype setup --download --model X` (and `--set-default`, `--progress json` NDJSON events so a GUI can render), catalog in `src/model_catalog.rs`, `voxtype info models`. Engines are separate compiled feature binaries (CPU baseline, AVX2/AVX512, Vulkan, CUDA 12/13, MIGraphX, OpenVINO); `voxtype setup gpu` and `setup variant` swap the binary via pkexec (src/setup/binary.rs, gpu.rs).

### 1.2 Feature list
Nine engines (Whisper, Parakeet, Moonshine, SenseVoice, Paraformer, Dolphin, Omnilingual, Cohere, OpenVINO Whisper) plus remote Whisper server and Soniox cloud (batch and realtime). Push-to-talk and toggle; secondary model via `model_modifier` key held; per-hotkey profile modifiers; cancel key; eager chunk processing (transcribe while still recording); streaming engines typed live; VAD (energy or Silero); filler word filter with per-language collision table (src/text/mod.rs `filler_collisions`, e.g. "um" is a real word in pt and de); spoken punctuation; replacement table; smart auto-submit (say "submit" to press Enter); auto_submit; Shift+Enter for newlines; `append_text`; LLM post-process pipe with timeout and prior-dictation context; media pause/duck via MPRIS over D-Bus (pause_media, duck_media, per-player ignore list); audio feedback themes; desktop notifications; Waybar/polybar JSON `voxtype status --follow --format json --extended` with icon themes; state file; meeting mode (chunked, diarization, echo cancel via dual capture, export md/txt/json/srt/vtt, Ollama summary); TUI configurator; file output mode and `record stop --wait --json` with exit codes (docs/INTEGRATIONS.md is a stable contract for embedding apps: ok/empty/timeout/error = 0/3/4/1); OpenAI-compatible local STT HTTP API (1.4.0 per CLAUDE.md); macOS (CGEvent, osascript, launchd, Hammerspoon, menubar); Omarchy plugin; DankMaterialShell setup; Quickshell widgets (engine picker, meeting controls); on-demand model loading with idle unload; multi-GPU select; CPU feature detection (src/cpu.rs) to refuse wrong binary.
CLI: `daemon, transcribe, setup {check,systemd,launchd,waybar,dms,model,gpu,npu,variant,onnx,parakeet,compositor {hyprland,sway,river},vad,osd,quickshell,macos,...}, config {show,get,set,schema}, info, configure, status, record {start,stop,toggle,cancel}, meeting {start,stop,pause,resume,status,list,show,export,summarize}, check-update`.

### 1.3 Text insertion (src/output/)
Files: `mod.rs` (chain), `wtype.rs`, `eitype.rs`, `dotool.rs`, `ydotool.rs`, `clipboard.rs` (wl-copy), `xclip.rs`, `paste.rs` (clipboard plus keystroke), `modifier_guard.rs`, `session.rs`, `streaming.rs`, macOS `cgevent.rs`, `osascript.rs`, `pbcopy.rs`.
- Default type-mode order (`DEFAULT_DRIVER_ORDER`, mod.rs): wtype, eitype, dotool, ydotool, clipboard (wl-copy), xclip. Configurable with `[output] driver_order` and `--driver=a,b`. If `driver_order` is set, `fallback_to_clipboard` is ignored; if not set and fallback flag true, clipboard is the tail. The chain just tries each in order: `is_available()` for wtype and eitype is only `which <tool>` (wtype.rs deliberately does not test WAYLAND_DISPLAY because systemd services may lack it), so on GNOME/KDE wtype is attempted, fails with "Compositor does not support the virtual keyboard protocol", then falls through. (Cost: one failed process spawn per dictation on GNOME unless the user sets `driver_order`. A compositor probe would avoid this.)
- Mode `clipboard`: wl-copy then xclip. Mode `paste`: wl-copy then synthesise `paste_keys` (default ctrl+v; "ctrl+shift+v" for terminals, `shift+insert` possible) via wtype, then eitype, then ydotool only (dotool excluded, no keystroke path), `restore_clipboard` (reads wl-paste incl. MIME types, restores after `restore_clipboard_delay_ms`). Mode `file`.
- Session detection (`session.rs`): WAYLAND_DISPLAY non-empty, else XDG_SESSION_TYPE, else DISPLAY=X11, default Wayland; routes clipboard tool (wl-copy vs xclip).
- wtype: flags `-s pre_type_delay`, `-d type_delay`, `wtype_shift_prefix` (`-P Shift_L -p Shift_L`) to stop the first CJK char being swallowed (Discord), newline as Shift+Enter option, curly quotes normalised to ASCII before typing (mod.rs `normalize_quotes`).
- eitype (libei, the way to type on GNOME and KDE): KDE zero-delay bug workaround (eitype.rs: KWin drops the tail of large bursts, so default delay forced to 1 ms on KDE); `eitype_xkb_layout/variant` and automatic per-transcription layout from detected language (`language_to_layout`, `language_to_variant` maps, defaults en->us, ru->ru, de->de; user table replaces defaults) - fixes "Character not found in keymap" when dictating Russian on a US layout (#180).
- dotool: layout-aware via `DOTOOL_XKB_LAYOUT/VARIANT` env; fast path uses `dotoold` + `dotoolc` (avoids ~700 ms uinput creation per call; very relevant for streaming where 60+ outputs per session). Caveat: layout applies to the daemon not the client; `dotoolc` cannot take variants, so hinted calls go through direct `dotool`. dotool does not switch the desktop layout; user must be on that layout.
- ydotool: socket discovery `$YDOTOOL_SOCKET`, `$XDG_RUNTIME_DIR/.ydotool_socket`, `/tmp/.ydotool_socket` (Fedora), `/run/user/UID/...`; CJK/non-ASCII unsupported (docs say so).
- modifier_guard.rs: before any keystroke driver, snapshot held modifiers with EVIOCGKEY on all keyboard devices (passive, no event consumption, re-enumerated each call for hotplug) and wait up to `modifier_release_timeout_ms`; on timeout skip all keystroke methods, copy to clipboard, notify the user. Skipped for clipboard-only chains because building the guard costs hundreds of ms on hosts with many input devices (#543).
- pre/post output hooks (`pre_output_command`, `post_output_command`) plus `voxtype setup compositor hyprland|sway|river` that installs a "suppress submap" so held Super does not turn typed letters into WM shortcuts. Note in generated config: do not bind Escape in the suppress submap, it drops wtype's first char (Hyprland #3165).
- Known failures documented (docs/TROUBLESHOOTING.md "Output Problems"): wtype unsupported on GNOME/KDE; first CJK char dropped; characters dropped (raise `type_delay_ms`); IBus reorders non-ASCII relative to ASCII when synthetic input is fast (GNOME GTK apps, ibus#2934, eitype#21): "Müll äöüß" becomes "üäöüß Mll"; only paste mode is atomic; `GTK_IM_MODULE=simple` is a per-app escape; wrong layout (y/z swap) with ydotool; dotoold layout inheritance; ydotool daemon not running; Soniox streaming typing while PTT held breaks libinput held-key state on Hyprland/Sway/River so daemon auto-promotes PTT to toggle.

### 1.4 Overlay and hotkeys
- Hotkeys: (a) built-in evdev listener (src/hotkey/evdev_listener.rs), needs `input` group, inotify on /dev/input for hotplug, skips virtual injection keyboards named for dotool/ydotool/xdotool (a stale uinput fd spun at 100% CPU, #445), release always ends the recording regardless of which modifiers are still held (modifiers gate only the press), on device-list change while held it synthesises a Released event (else recording runs to max_duration; the ydotool driver creates a virtual keyboard per paste which triggers exactly this, #556); (b) compositor bindings: Hyprland `bind`/`bindr`, Sway `bindsym --release`, River `map -release` for push-to-talk; KDE and GNOME: toggle only ("KDE does not support key-release"), set `[hotkey] enabled=false`. KDE grabs Meta+Shift/Ctrl/Alt before evdev sees them; use F13-F24, ScrollLock, or compositor shortcut.
- OSD: three frontends, selected by `[osd] frontend`: `gtk4` (src/bin/voxtype_osd_gtk4.rs, gtk4-layer-shell, Layer::Overlay, keyboard mode none, click-through input region via cairo Region, top-anchor with fractional top_margin to line up with swayosd), `native` (src/bin/voxtype_osd_native: SCTK + wgpu + egui-wgpu), `quickshell` (quickshell/*.qml, `OsdSurface.qml`, `shell.qml`, launched through `qs -d -p`). Dispatcher `voxtype-osd`; shared logic in src/osd/ (ipc.rs level socket with reconnect, visual.rs peak hold and envelope, theme.rs Omarchy theme watcher, recipe.rs declarative layers: bars/waveform/pulse/ring/meter/icon/label with sources peak/rms/vad/state). States: idle hidden; recording red tint with waveform; streaming blue; transcribing amber. Quickshell popups toggled by touching flag files under `$XDG_RUNTIME_DIR/voxtype/`.
- GTK4 crash fix worth knowing (src/osd/gtk_env.rs): GTK before 4.22.5 / 4.23.3 SIGSEGVs when Hyprland resends linux-dmabuf feedback (output hotplug, lid close); workaround sets `GDK_WAYLAND_DISABLE=zwp_linux_dmabuf_v1`.
- GNOME: no OSD. Status via Waybar-style state file, notifications. `$XDG_RUNTIME_DIR/voxtype/state` readable by any shell extension.

### 1.5 Packaging and doctor
AUR (`voxtype`, `voxtype-bin`, `voxtype-bin-rc`), .deb (debian/, nfpm.yaml), .rpm (packaging/rpm/voxtype.spec), AppImage, Homebrew cask (macOS), Nix flake with NixOS and home-manager modules (nix/), Docker multi-variant reproducible builds (Dockerfile.*), systemd user unit (`PartOf=graphical-session.target`, `Wants=ydotool.service`, Restart=on-failure). `voxtype setup check` (deps/config check), `setup systemd`, `setup waybar`, `info`, `status`. Test matrix Dockerfiles for arch/debian/fedora/ubuntu (testing/). docs/smoke_tests/ holds ~45 manual test scripts (dotool fallback, layout, rapid successive recordings, signal handling, packaged upgrade).

### 1.6 Notable techniques
Passive EVIOCGKEY modifier snapshot; hotplug-safe hotkey reset; dotoold fast path; per-language XKB hint; PTT auto-promote to toggle when live typing; compositor submaps; OSD as a supervised child with exponential backoff; JSON progress events for GUI-driven model downloads; `record stop --wait --json` exit-code contract; filler list collision table by language; MPRIS via D-Bus replacing playerctl (silently broke when Omarchy removed playerctl); GTK dmabuf workaround.

## 2. hyprwhspr (Python, MIT) - `hyprwhspr`

### 2.1 Architecture
- One long-running systemd user service `lib/main.py` (class `hyprwhsprApp`, mixins in `lib/src/app/`: `recording.py`, `shortcuts.py`, `silence.py`, `feedback.py`, `control.py`, `recovery.py`). Threads: evdev event loop (`lib/src/global_shortcuts.py`), audio capture (`audio_capture.py`, sounddevice), control server (`recording_control_server.py`: FIFO at `$XDG_RUNTIME_DIR/hyprwhspr/recording_control` accepting `start stop release cancel submit model_unload model_reload`, plus a single-subscriber capture socket for `record capture`), udev monitor for audio hotplug (`device_monitor.py`, `udev_monitor.py`), PulseAudio/PipeWire monitor (`pulse_monitor.py`), logind suspend/resume monitor over D-Bus (`suspend_monitor.py`), clipboard-restore timers.
- Data flow: evdev shortcut or FIFO command -> `audio_capture` -> optional Silero VAD (`pywhispercpp_use_vad`, `onnx_asr_use_vad`) -> backend (`lib/src/backends/`: pywhispercpp, faster-whisper, onnx-asr (Parakeet), parakeet.cpp, Cohere, Qwen3-ASR, REST, realtime WebSocket) -> `text_injector.preprocess_text` (word overrides, fillers, symbol replacements, hallucination markers `hallucination.py`) -> `post_transcription_hook` -> `TextInjector` -> clipboard+paste or direct type -> optional Enter.
- Config: JSONC `~/.config/hyprwhspr/config.json`, 112 keys, JSON Schema `share/config.schema.json` with a unit test that keeps `ConfigManager.default_config` and the schema in sync (tests/test_config_schema_sync.py); `hyprwhspr config validate`.
- Models: `hyprwhspr model {download,list,status,unload,reload}`; backends installed into private venv by `backend_installer.py` (3.3k lines: prebuilt wheels with SHA-256 manifest, Vulkan/CUDA variants, glibc gating). `docs/backends/MEMORY.md` per-model memory table and unload/reload for freeing GPU.

### 2.2 Feature list
Recording modes (docs/usage/RECORDING_MODES.md): toggle, push_to_talk (with latch: hold past `push_to_talk_lock_seconds` then release to stay recording), auto (tap under 400 ms = toggle, hold = PTT), continuous (each pause pastes, calibrated silence threshold), long_form (pause/resume/submit, segments autosaved to disk for crash recovery). `silence_timeout` auto-stop. Primary, secondary-with-language, cancel shortcut. Word overrides, filler filter, hallucination markers, symbol replacements, trailing space, script-aware (CJK no space, `text_script.py`). Audio ducking or MPRIS pausing (`playback_suppressor.py`: pause, then duck leftovers). Mute detection cancels recording if mic is muted. `keepalive_stream` (keeps mic stream open to cut start latency; shows mic indicator). Audio feedback sounds. Mic OSD (waveform, vu_meter, pill with live transcript on realtime backends), Waybar module, Noctalia plugin, GNOME extension (contrib). Live typing for append-only realtime models (`live_typing.py`, holds back opening words that could become a hallucination marker). Recovery commands: `record copy-last|paste-last|clear-last` (text only in memory, never audio). `record capture` streams transcription to stdout; `--trace-processing`. `hyprwhspr transcribe FILE`. Per-app rules (`applications` map: custom paste chord or disable injection for an app, e.g. password manager). CLI: `setup, setup auto, install repair/status, update, config {validate,init,show,edit,secondary-shortcut,focused-window}, waybar, noctalia, mic-osd, systemd, model, status, validate, test, transcribe, keyboard {list,test,configure,detect}, record`. Managed install (docs/MANAGED_INSTALLATION.md: verified release update, repair, uninstall --purge --keep-models).

### 2.3 Text insertion (lib/src/text_injector.py, 2k lines; docs/usage/PASTE.md, docs/integrations/DESKTOPS.md)
Core idea: clipboard-first. Save clipboard (all MIME types via wl-paste), wl-copy text, wait `clipboard_settle_delay` (0.15 s), send a paste chord, restore previous clipboard after `clipboard_clear_delay` (5 s) only if injection succeeded. Failure leaves text on clipboard, skips auto-submit.
Chord sender order in `_paste_via_clipboard`:
1. `hyprland_paste_backend: ydotool` explicit: ydotool only, no fallback.
2. X11 session and xdotool: xdotool key.
3. Hyprland: native `hyprctl dispatch sendshortcut`, then wtype, then ydotool.
4. Other Wayland: wtype, then ydotool.
5. Last resort: ydotool "slow" path with 15 ms and 10 ms pauses, and always releases pressed modifiers in `finally`.
6. No tool at all: text stays on clipboard, no restore.
Paste chord choice: focused-window class (`_get_active_window_info`: `niri msg --json focused-window`, `hyprctl activewindow -j`, xdotool+xprop on X11, AT-SPI on GNOME/KDE) against a terminal list -> Ctrl+Shift+V else Ctrl+V; `paste_mode` override; per-app `applications` rules.
GNOME Wayland special path (Mutter blocks wtype): if ASCII-only and the active layout keeps ASCII where US does, type directly with `ydotool type --key-delay 5 --key-hold 5`; otherwise clipboard paste via ydotool chord. "Layout is type-safe" is decided by compiling the real XKB keymap with xkbcli (`lib/src/keyboard_layout.py`: compares keys carrying printable ASCII to US positions), not by a country code list, so pl is direct but pl(dvorak), de, fr are not. Active layout read from `gsettings org.gnome.desktop.input-sources mru-sources`, then `localectl`, then `XKB_DEFAULT_LAYOUT`; cached with short TTL. Non-Latin layouts (Thai, Russian, Arabic): chord keycode for V has no `v` keysym, so the tool temporarily switches the GNOME input source to a Latin one (`gsettings set ... current N`), waits 120 ms, sends chord, restores. Non-QWERTY layouts: `paste_keycode_wev` (user reads a keycode with `wev`).
Other details: after wtype paste, release stuck modifiers through ydotool (wtype's virtual-keyboard modifier state can leave uinput layer confused); `ydotool_modifier_overrides` for remapped Ctrl/CapsLock; private `ydotoold` child on its own socket (`lib/src/ydotoold_session.py`: lazy start on first uinput use, restart once if dead, 1.1 s settle because the socket appears before the device works, `ExecStopPost` pkill safety net in config/systemd/hyprwhspr.service); Hyprland NumLock bug (#283): native dispatcher clears the lock state seen by the focused app, workaround is ydotool backend; stream injection holds back words, saves clipboard once per stream and restores once at end; secrets: "disabled for app" means do not even touch the clipboard.
No libei/eitype, no IBus, no portal, no dotool.

### 2.4 Overlay and hotkeys
- Hotkeys: evdev with optional device grab (`grab_keys`, uinput clone re-emits non-shortcut keys; 10 retries with exponential backoff because the kernel may not have released the previous grab after a quick restart; error message points to Espanso/keyd/kmonad conflicts); hotplug via udev; `keyboard_device_names` allowlist; `keyboard configure/detect`. `external_bindings: true` lets the compositor own the key: toggle via `hyprwhspr record toggle`, PTT via writing `start` on press and `release` on release to the FIFO (Hyprland `bind`/`bindr`). Works with niri, Sway, KDE, GNOME custom shortcuts. Compositor key release only exists on wlroots-ish compositors.
- Overlay (lib/mic_osd/): GTK4 plus gtk4-layer-shell window (`window.py`) at bottom centre; runs as a daemon spawned once and toggled with SIGUSR1/SIGUSR2 to avoid spawn latency (`runner.py`), level feed written as a file at 30 Hz, state file for the visualizer; libgtk4-layer-shell must be LD_PRELOADed ahead of libwayland, with a probe subprocess to confirm it, strip duplicates and fall back to a bundled runtime. Visualisations: waveform, vu_meter, pill (idle dots, live bars, travelling wave, error pulse, checkmark). Theme follows Omarchy and Noctalia.
- GNOME (no layer-shell): notification presenter (`notification_presenter.py`: recording, transcribing (persistent, no timeout), success/error transient; AGENTS.md insists every path out of processing sets success/error or hides, or the banner sticks) and an opt-in GNOME Shell extension (`contrib/gnome-shell-extension/hyprwhspr-waveform@ninyawee.github.io/extension.js`): `St.BoxLayout` with `reactive: false`, `can_focus: false`, added with `Main.layoutManager.addChrome`, reads `recording_status`, `audio_level`, `transcript_preview` files in `$XDG_RUNTIME_DIR/hyprwhspr/`, reacts to `monitors-changed`. Very close to what Whispr already plans.

### 2.5 Packaging and doctor
AUR (`hyprwhspr`, `hyprwhspr-git`), `curl | bash` installer (`scripts/install.sh`, copies to website), managed releases for Debian/Ubuntu/Fedora/openSUSE (docs/MANAGED_INSTALLATION.md), Nix flake and module (nix/), systemd user unit (config/systemd/hyprwhspr.service: `ExecStartPre` waits up to 15 s for a usable Wayland socket or DISPLAY, `ExecStopPost` kills leftover virtual keyboards and the private ydotool socket). `hyprwhspr setup` (interactive, offers AT-SPI enablement), `setup auto`, `validate` (session env, graphical-session.target), `status`, `test --live`, `config validate`, `install status`, `install repair`, diagnostics module with allowlisted read-only report (`lib/src/diagnostics.py`, `run_diagnostics(report, json)`), dependency plan fingerprint that warns when deps changed since setup (`dependency_plan.py`).

### 2.6 Notable techniques and troubleshooting
- docs/TROUBLESHOOTING.md: service starts before `WAYLAND_DISPLAY` exists (use `dbus-update-activation-environment --systemd`, uwsm, check `graphical-session.target`, `RefuseManualStart=yes` on some distros; startup falls back to the newest `wayland-*` socket); NIRI_SOCKET missing in systemd env; recording cuts off after seconds when WirePlumber suspends the shared ALSA card (fix: `session.suspend-timeout-seconds = 0` in a wireplumber conf.d file; app reports "Microphone stalled"); default source ending `.monitor` selected by mistake; mic indicator on while idle (keepalive stream); stuck recording (`record cancel`); NumLock after paste on Hyprland.
- AGENTS.md contracts worth stealing as practice: config keys must match schema via a test; patch-target hygiene tests; "NotificationPresenter processing state must always be resolved"; wheels never overwritten, checksum-verified; GPU build that fell back to CPU is recorded and warned at start.
- `hallucination.py`: stock Whisper phantoms list ("thank you", "thanks for watching", etc.), prefix-aware so streamed partials are held until they cannot be a marker.
- Suspend/resume and audio hotplug recovery mixin; zero-volume mic detection file; recovery request/result files.
- Parakeet via onnx-asr (CPU "wild speeds"), Orukeet benchmark docs (docs/benchmarks/).

## 3. vocalinux (Python/GTK3, AGPL-3.0) - `vocalinux` (read for ideas only)

### 3.1 Architecture
- One GTK3 tray process (`src/vocalinux/main.py`) with: tray (`ui/tray_indicator.py`, Ayatana AppIndicator), Settings (`ui/settings_dialog.py` 10k lines), `recognition_manager.py` (4.9k lines: VAD segmentation + engine dispatch table + model lock), `audio/capture.py` (PortAudio) and `audio/pipewire.py`, `speech_recognition/silero_vad.py` with amplitude fallback, `engines/` (whisper.cpp default via pywhispercpp, OpenAI Whisper, Faster Whisper, VOSK, Parakeet, remote HTTP API), `command_processor.py` (voice commands), `custom_dictionary.py`, `post_processor.py` (user script via stdin/stdout, 10 s timeout, falls back to original on failure), `text_injection/` (below), `ui/keyboard_backends/` (evdev with grab+uinput clone, pynput), `dbus_service.py` (`com.vocalinux.Vocalinux` Toggle/Start/Stop), `suspend_handler.py`, `auto_pause_monitor.py` (unload model while listed games run), `model_keepalive.py` (idle unload 60 s to 3600 s), `gateway_embed/` (optional local VocaGateway container), `single_instance.py`.
- Data flow (docs/ARCHITECTURE.md): capture -> VAD segmentation -> bounded queue -> recognition worker -> engine -> dictionary and voice commands -> single ordered post-processing worker -> `TextInjector` or in-app Dictation Pad.
- Config: JSON `~/.config/vocalinux/config.json`, `DEFAULT_CONFIG` in `ui/config_manager.py` with recursive overlay; sections speech_recognition, audio, sound_effects, playback_duck, shortcuts, ui, general, auto_pause, model_keepalive, text_injection, history, post_processing, dictionary, advanced, updates, proxy. First run seeds language from system locale. Model checksums file `utils/model_checksums.txt`.

### 3.2 Feature list
Tray menu, searchable Settings with simple/advanced model setup; push-to-talk (default hold Right Alt) and toggle (double-tap modifier); per-language shortcuts; language "auto" / "layout" (follow active keyboard layout) / pinned; voice commands (new line, punctuation, delete that, capitalize, all caps; localized punctuation phrases); custom dictionary (docs/CUSTOM_DICTIONARY_DESIGN.md); post-processing script; transcript history (tray, optional JSONL persistence so failed injection does not lose text); Dictation Pad window as Wayland-safe fallback (`dictate_to_pad`); Transcribe File with TinyDiarize; audio ducking of other apps; start/stop sounds; proxy settings for downloads; update checker; D-Bus external activation; log viewer; autostart via XDG; Vulkan GPU; model download only on explicit confirm. CLI flags: `--debug --wayland --toggle --start --stop` etc. (main.py arg parser) UNVERIFIED for full list.

### 3.3 Text insertion (src/vocalinux/text_injection/text_injector.py 3.4k lines, ibus_engine.py 1.9k, remote_desktop_portal.py, focused_window.py)
Backends: IBus engine, RemoteDesktop portal, wtype, ydotool, xdotool, clipboard. Pin with `text_injection.backend` or env `VOCALINUX_FORCE_BACKEND` (`auto|ibus|portal|wtype|ydotool|xdotool`).
Autodetect (`_check_dependencies`):
1. IBus first (sends Unicode, immune to layouts), only if ibus-daemon is running, user has no explicit non-IBus GTK/QT/XMODIFIERS, and the compositor bridges IBus to native Wayland clients. Denylist of unbridged compositors: cosmic, sway, hyprland, wayfire, river, niri, labwc, weston, overridden when `pgrep ibus-wayland` finds the IBus 1.5.32+ input-method-v2 bridge. On KDE Plasma Wayland IBus counts as bridged only if KWin `/VirtualKeyboard` D-Bus property `available` (Plasma 6) or `enabled` (Plasma 5) is true (queried via gdbus). Failure mode: IBus `commit_text` reports success but text is dropped in native Wayland windows (#478, #485).
2. Else on X11: xdotool.
3. Else on Wayland: RemoteDesktop portal (only sanctioned path; no uinput, works in Flatpak; asks once, persists `restore_token` in a 0600 file under XDG data; keysym based via `NotifyKeyboardKeysym`, Unicode char to keysym), then ydotool (if ydotoold ready), then wtype, then xdotool on XWayland. On KDE, ydotool goes before the portal because KWin's portal scrambled letter case (#911). Flatpak without a Wayland socket prefers ydotool.
- Runtime failover: IBus failure -> non-IBus backend; portal failure -> "demote" to next backend, resuming from the untyped remainder (`_PartiallyTyped` tracks exactly how many chars landed so no duplication); wtype "compositor does not support" error -> xdotool via XWayland and a KDE-specific hint; final failure -> clipboard copy of only the untyped remainder plus notification plus error sound.
- XWayland detour: `focused_xwayland_client_without_ibus` (xdotool active window pid) routes that segment through xdotool when the focused XWayland app has no IBus input context (#972).
- IBus engine design: a custom engine "vocalinux" registered through `register_component` from its own process, a Unix socket server (peer credentials verified) that commits text; it is activated only for the duration of an injection ("scoped"), previous engine and XKB layout captured and restored afterwards (fixes of layout clobber #292, #664, multi-layout collapse); waits for client focus; retries 3 times, restarts the engine process if the socket vanished.
- Unicode and layouts: ydotool and xdotool type US keycodes, so non-ASCII or non-US layout text goes through clipboard paste (#362, #657, #787); paste chord resolves the key that types Latin `v` on the active layout; terminals detected by app-id token set (`focused_window.py`: Hyprland `hyprctl`, niri, sway tree, X11 xprop; xprop preferred because `xdotool getwindowclassname` aborts on KWin's property-less XWayland window) -> Ctrl+Shift+V; setting `paste_shortcut`; clipboard restored unless holding non-text content (then it types instead). `ydotool type --key-delay` kept above 0 to avoid the Shift-leak ("Can you" -> "CAN YOu"); typing is chunked at 200 chars with scaled timeouts so shutdown can abort.
- `_wait_for_modifiers_released` (evdev `active_keys()`, 15 ms poll, default max 1.0 s, env `VOCALINUX_INJECT_MODIFIER_WAIT`, sanitises `inf`).
- ydotoold management: socket path candidates, `_ensure_ydotoold`, install guidance text, warning when `ydotool.service` is enabled globally (also starts in greeter sessions).
- Whitespace-only segments skipped, but "\n" still typed (voice command "new line" #955).

### 3.4 Overlay and hotkeys
- Hotkeys: evdev backend (`ui/keyboard_backends/evdev_backend.py`, 2k lines): `EvdevDeviceHub` shared device layer; grabs keyboards (EVIOCGRAB) and re-emits via uinput clone so the shortcut keys never reach apps; without uinput access falls back to ungrabbed listening; keyboards with pointer axes (Logitech K860) and remapper virtual keyboards (keyd) are monitored ungrabbed; a keyboard with a held key or queued events at startup is left ungrabbed (stuck key prevention, #941); on release the backend reads live kernel key state and releases phantom keys on the clone; pynput for X11. GNOME Shell X11 prefers evdev (#963). External activation via D-Bus `vocalinux --toggle` for KDE/GNOME shortcut: toggle only, no PTT because the compositor never reports key release. Pure-modifier gestures (double-tap Right Alt, hold Right Alt for PTT) are a nice design that avoids compositor shortcut conflicts.
- Overlay (`ui/dictation_overlay.py`): GTK3 click-through, non-focusable (`accept_focus false`, `focus_on_map false`, NOTIFICATION type hint, keep above, RGBA visual), soft use of GtkLayerShell (OVERLAY layer, bottom/left/right anchor) when supported, 30 fps orb pulsing with live mic level; green listening, amber processing. GNOME Wayland fix: window mapped at startup so the first recording does not steal focus (#998).

### 3.5 Packaging and doctor
install.sh (`--dev --auto --test --skip-models --skip-system-deps --rebuild-whispercpp`), `install.d/` modules, distro package map (`scripts/distro-package-map.yaml`, generated), .deb/.rpm via nfpm (`packaging/native`), AppImage x86_64/aarch64 (`packaging/appimage`), AUR source and -bin (`packaging/aur`), Flatpak with a self-hosted signed OSTree remote (Flathub rejected; `docs/FLATPAK_REMOTE.md`), Snap (store denied `uinput` plug, so Snap uses portal), PyPI, Nix flake and modules. XDG autostart (not systemd). `vocalinux --debug`, in-app log viewer, `scripts/verify_release.py`, wheel built reproducibly at x86-64 baseline (older CPUs crashed otherwise).

### 3.6 Notable techniques and failures
IBus silent drop on unbridged compositors; KWin VirtualKeyboard check; KDE portal case scrambling; portal request handle tokens had to be unique (missing GNOME consent dialog and 15 s timeout, #996); partial-typed accounting for fallback; distro layout of GI_TYPELIB_PATH; AppIndicator library churn (ayatana glib preferred); stale `XDG_SESSION_TYPE=x11` with a live Wayland socket (live socket wins, #752); portable x86-64 build; opt-in persistence of dictated text because privacy (#758).

## 4. Cross-repo comparison for Linux insertion

| Desktop | voxtype default | hyprwhspr | vocalinux |
|---|---|---|---|
| Sway/Hyprland/river/niri | wtype | native dispatch then wtype then ydotool (clipboard paste) | wtype/ydotool (IBus only if ibus-wayland) |
| GNOME Wayland | wtype fails, then eitype (libei) | ydotool type if ASCII+US-like layout, else ydotool chord paste with layout switch | IBus engine (scoped), else portal |
| KDE Wayland | wtype fails, then eitype (min 1 ms delay) | ydotool chord | IBus if KWin VK on, else ydotool, then portal |
| X11 | dotool/ydotool/xclip | xdotool paste | xdotool |
| Overlay on GNOME | none | notifications + optional shell extension | GTK3 overlay (focus fix) |
| Key release PTT on GNOME/KDE | no (toggle) | no (toggle) or evdev grab | no (toggle) or evdev grab |

Common failure root causes: (1) compositor lacks virtual-keyboard protocol (GNOME, KDE); (2) key synthesis ties to physical keycodes and the active layout; (3) held modifiers turning typed text into shortcuts; (4) IBus reordering or silently dropping; (5) uinput permission and daemon lifecycle; (6) races of clipboard restore versus slow apps.

## 6. Things to avoid
- Trying a known-failing backend every time (voxtype wtype on GNOME).
- Relying on IBus `commit_text` reporting success; it lies on unbridged compositors (vocalinux).
- Grabbing keyboards (EVIOCGRAB) by default; it caused stuck keys, remapper conflicts, and 100% CPU loops across both evdev implementations.
- Typing PTT live text while the PTT key is held on wlroots compositors (voxtype auto-promotes to toggle).
- Spawning ydotoold as a shared global service (greeter sessions; vocalinux warns); if used at all, keep a private socket as hyprwhspr does.
- Copying vocalinux code (AGPL).
